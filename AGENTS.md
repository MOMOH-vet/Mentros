## Efficient Workflow

**1. Используй локальные инструменты до LLM, когда интеллект не требуется.**

Для механической обработки больших объёмов данных сначала используй детерминированный локальный инструмент: MarkItDown для преимущественно текстовых документов, `rg`/Git search для кода, `jq` для JSON, shell/Python для фильтрации логов и структурированных данных.

Начинай с компактного представления. Обращайся к исходному документу, полным логам, изображениям или более широкому контексту, если сокращённого представления недостаточно или оно могло потерять значимую информацию.

Не сокращай необходимые проверки ради экономии токенов.

**2. Исследуй dependency cone текущей задачи.**

Для локальной задачи сначала найди существующую реализацию, callers/references, прямые зависимости, связанные конфиги, тесты и существующие аналогичные механизмы.

Расширяй исследование дальше только когда обнаруженные зависимости дают для этого причину.

Перед созданием нового сервиса, компонента, helper, API-path, локализации, UI-механики или другой реализации сначала убедись, что соответствующий механизм уже не существует в проекте.

Цель — не читать репозиторий целиком, но и не создавать параллельную архитектуру или дубли.

**3. Используй и создавай повторяемую автоматизацию.**

Перед ручным выполнением повторяемой операции сначала проверь существующие `work/`, `scripts/`, `tools/`, release/build/deploy utilities и доступные инструменты `visual-workbench`.

Если надёжный рабочий скрипт уже существует — используй его вместо повторного ручного выполнения той же процедуры.

Если механическая процедура регулярно повторяется и хорошо формализуется, разрешено создать небольшой детерминированный скрипт в предусмотренной проектом sandbox/work области и затем переиспользовать его.

Не создавай framework или сложную инфраструктуру ради одноразовой простой операции.
